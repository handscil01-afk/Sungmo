# 손잡다 야구 고도화 최종 점검표

작성: 2026-11-11. 원래 요청서의 점검표 원문은 저장소에 없어서, 설계서(`docs/OVERHAUL.md`)의 기능 목록, 사용자 피드백 9개, 단계별 "끝 기준"을 바탕으로 새로 만들었습니다.
각 항목에 **어떻게 확인했는지**와 **결과**를 적었습니다. 사람이 실제 기기로 확인해야 하는 것은 맨 아래 4번에 따로 모았습니다.

## 3. 기능별 점검

### 3-1. 경기 규칙과 균형
| 항목 | 확인 방법 | 결과 |
|---|---|---|
| 모든 모드(간단·공 하나씩·정밀·감독)가 끝까지 진행되고 규칙 위반이 없음 | `sim.js`, `e2e.js` | 통과 |
| 같은 경기 글(문장)이 단계 사이에 바뀌지 않음(의도하지 않은 변경 방지) | `sim.js`의 글 해시 | 통과 |
| 균형: 강하게 < 보통 ≈ 맞히기, 장타는 강하게가 가장 많음 | `sim.js` 균형 표 | 통과 |

| 균형: 팀 득점 5점 안팎 | `sim.js` | 5.5점으로 거의 맞음 (타율 .306, 홈런 0.88, 도루 경기당 0.47) |
| 파울 플라이를 물리 계산으로 판정 | `sim.js`, 별도 확인 | 통과 (파울의 약 3.5%가 잡힘) |

### 3-2-2. 야구 규칙과 말이 맞는지 (사용자 지적 후 점검, 2026-11-13)
| 항목 | 확인 방법 | 결과 |
|---|---|---|
| 2루타·3루타는 공이 떨어질 때 "안타!"까지만 말하고, 타자 주자가 그 베이스에 닿은 뒤에 말함 | `caster.js`가 말하는 시각과 타자 주자 도착 시각을 비교 | 수정. 예전에는 약 6초 일찍 말했음 |
| 진동도 결과가 정해지는 순간에 울림(공을 치자마자 울리지 않음) | 코드 확인 | 수정 |
| "끝내기!"(소리, 글씨, 마무리 장면)는 그 결과에서 실제로 끝내기로 경기가 끝날 때만. 육성·건너뛰기에서 내 타석 뒤에 경기가 끝까지 진행돼도 내 타석에는 붙이지 않음 | `e2e.js`, `caster.js` | 수정 |
| 끝내기는 승부를 가르는 점수가 들어오는 순간 경기가 끝남: 결승점 뒤의 득점은 인정하지 않고, 타석 도중 폭투·포일·도루로 점수가 나도 바로 끝남 | `sim.js`(끝내기 경기는 홈런이 아니면 점수 차가 정확히 1점) | 수정 |
| 끝내기 안타는 결승 주자가 나아간 베이스 수까지만 안타로 인정(홈런은 모두 인정) | `sim.js` | 수정 |
| 평균자책점은 자책점으로 계산: 실책으로 들어온 점수는 제외 | `sim.js`(비자책점이 실점보다 많지 않음) | 수정. 실책 때 나간 주자의 득점을 단순화해서 계산함 |
| 중계 말이 실제 상황과 맞음: "1루에서 아웃"은 타자가 1루에서 아웃일 때만, "떨어집니다"는 땅볼 안타에 쓰지 않음, "펜스까지 굴러갑니다"는 담장을 맞았을 때만, "평범한 뜬공"은 직선타에 쓰지 않음 | `caster.js` | 수정 |
| 경기 기록 일관성(안타·득점·삼진·볼넷 합계, 승패 투수, 이닝별 점수, 아웃 수) 600경기 | 별도 점검 | 위반 없음 |

| 8 | 한 번 쓰던 기기에서 앱을 새로 열었을 때, 이전 설정·저장 경기·육성 선수가 그대로 있는지 | 업데이트 전 저장이 있는 기기에서 |

## 5. 하지 못했거나 미달인 것 요약

- 사구(몸에 맞는 공)가 기록에서 볼넷에 합쳐져 있음. 평균자책점의 자책 구분이 단순화되어 있음.
- 약 90곳의 글이 아직 예전 방식이고, 효과음의 일부와 예전 효과 이름 추측 코드가 남아 있음. 겉으로 보이는 기능 변화가 없고, 글 일부가 무작위로 고른 문구라 옮길 때 글이 바뀔 위험이 커서 의도적으로 미뤘음.
- 새 녹음(수비수, 송구, 이닝 끝 해설, 새 말투)은 사람이 녹음해야 함(`docs/VOICE-SCRIPT.md`).
