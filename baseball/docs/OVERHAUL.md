# 손잡다 야구 고도화: 전체 진단과 설계 (1단계 결과)

작성: 2026-11-10. 이 문서는 구현 세션(2단계)이 그대로 따라 할 수 있는 작업 지시서다.
구현 세션은 **한 번에 한 단계(Phase)만** 하고, 단계가 끝날 때마다 아래 "단계마다 돌릴 시험"을 모두 통과시킨 뒤 `main`에 올린다.

- 저장소 규칙: 저장소 맨 위 `CLAUDE.md` (빌드 없는 JS, PWA, 한국어 UI, `sw.js` 캐시 버전, 카톡 다시 열기 스크립트, 커밋 전 Playwright 확인).
- 지금까지의 계획·이력: `baseball/PLAN.md`, 녹음: `baseball/voice/README.md`.

## 1. 지금 구조 (유지할 뼈대)

빌드 없는 일반 `<script>` 21개, 약 8,800줄. **경기 계산은 화면과 분리되어 있고(engine·playsim), 두 화면 방식(시청각장애인 모드 `a11y`, 화면 보며 하기 `gfx`)이 같은 계산·같은 화면 정의(질문 + 번호 선택지)를 쓴다.** 이 뼈대는 좋으므로 유지한다.

## 4. 핵심 설계

### 4.1 사건 목록 (A1 해결, 모든 것의 바탕)

`flush(G)`가 돌려주는 값에 `events` 배열을 더한다. 기존 `lines`·`fx`는 **한동안 그대로 두고**(호환), 읽는 쪽을 하나씩 옮긴 뒤 마지막에 `fx` 추측 코드를 지운다.

```js
// 예: 유격수 땅볼 아웃
[ { k:'pitch', n:12, type:'SL', vel:132, zone:6, call:null },
  { k:'contact', q:0.42, ev:0.5, type:'gb', dir:-0.4, t:0 },
  { k:'field', pos:'SS', who:'김철수', t:1.2, how:'ground' },
  { k:'throw', from:'SS', to:0, t0:1.9, t1:3.1 },
  { k:'call', base:0, out:true, runner:-1, t:3.1, close:false },
  { k:'pa', result:'go', outs:1 },
  { k:'next', batter:4, outs:1, bases:[null,null,null] } ]
```

- 종류: `pitch call(strike/ball) swing contact foul field catch drop throw call(base) score steal pick wp review sub pa inning game`.
- `playsim`의 `ev`·`call`·`runners`가 이미 대부분의 재료다. `applyPlay`에서 사건으로 옮겨 담는다.
- **글(`emit`)도 사건에서 만든다**: `describe(events) → lines`. 그러면 문자 중계와 음성 중계가 같은 정보에서 나온다(요구 4번 "문자 중계와 음성 중계는 동일한 경기 정보").
- `G.inningLog`: 이닝마다 `{ runs, hits, walks, errors, lob, ks, dp }`를 쌓아 이닝 끝 중계가 고른다(C1).

### 4.2 숫자 체계 (피드백 6)

숫자판은 지금처럼 전화기식/컴퓨터식을 설정으로 고른다(`zoneNum`). 왼손 타자 좌우 뒤집기(방향 배치)도 그대로.

| 상황 | 1~9의 뜻 | 지금 | 바꿀 것 |
|---|---|---|---|
| 투구 위치 | 존 9칸 | 있음 | 그대로. 존 밖은 "얼마나 붙일지"(안쪽·구석·빼기)로 이미 표현 → **0번 = 존 밖 유인구 빠른 선택** 추가 |
| 구속 | 1(가장 느림)~9(전력) | 3단계 | `w`를 1~9로. 5가 보통. 구속 `+(w-5)×1.2km`, 제구 오차 `×(1+(w-5)×0.07)`, 체력 `+(w-5)×0.12`, 느린 공은 타이밍 빼앗기 보너스. 옛 값 1·2·3은 3·5·8로 읽음 |
| 노리는 코스 | 존 9칸 (타자) | 없음 | 새 선택 "노려 치기": 고른 칸과 실제 공의 거리로 맞히기·정확도 보정. 맞으면 `+`, 반대쪽이면 `−`. 선구안이 높으면 벌점이 작음. 안 고르면(5 = 가운데) 보정 없음 |
| 타격 강도 | 1(맞히기)~9(풀스윙) | 3가지 | `contact/swing/power`를 1~9로 이음(3·5·8이 옛 값). 맞히기 쪽이 지금 너무 좋으므로 B3와 함께 조정 |
| 송구 | 1·2·3·4 = 1루·2루·3루·홈 | 없음 | 4.3 |

"숫자 하나가 정답"이 되지 않게: 노린 코스가 맞아도 구종 타이밍·구위·컨택이 그대로 곱해지고, 투수 쪽에서는 타자가 최근 노린 코스를 "포수 힌트"로 흐릿하게만 알려 준다(심리전).

정밀 모드의 "직접 고를 것" 설정(`picks`)에 새 항목(구속 9단계, 노려 치기, 송구)을 더해, **안 고르는 항목은 지금처럼 컴퓨터가 채운다**(초보·빠른 진행 유지).

### 4.3 송구 선택 (피드백 5, B4)

`simPlay`를 두 번에 나눈다.

1. `simField(G, bb)` → 누가 언제 어디서 잡는지까지 계산하고, 송구 후보를 만든다:
   `opts = [{ base:0, eta:1.3, runnerEta:1.6, pOut:0.9 }, { base:3, … }]` (갈 수 없는 베이스는 빠짐).
2. 수비가 사람이고 후보가 둘 이상이며 설정이 켜져 있으면 `G.pendingThrow = { opts, deadline }`을 세우고 화면이 묻는다: "유격수 김철수가 잡았습니다. 어디로 던질까요? 1번 1루(여유), 2번 2루(아슬아슬), 4번 홈(늦음)".
3. `resolveThrow(G, base)` → 나머지(병살 연결, 다른 주자)를 계산해 사건을 완성한다.

- 컴퓨터·맡기기·시간 초과(6초, 설정으로 끔)는 지금의 자동 판단(`gbThrows`의 `tgt`)을 쓴다.
- 그림은 잡는 순간에서 멈췄다가 고르면 이어서 재생한다. 중계도 그때까지만 말한다.
- 뜬공을 잡은 뒤 태그업 주자, 안타 뒤 외야 송구에도 같은 창을 쓴다(후보: 2루·3루·홈·"던지지 않음").
- 온라인: `pendingThrow`는 방장 상태에 들어가고, 수비 쪽 기기만 답할 수 있다(권한 검사는 `online.js`의 기존 `a.k` 처리에 `throw` 추가).

### 4.4 히트앤런 (피드백 8, B5)

엔진에는 이미 있다(`Bsel.k === 'hitrun'`: 주자 먼저 출발, 타자는 웬만하면 맞힘, 헛스윙이면 도루 판정, 직선타면 귀루 못 해 더블 아웃). 할 일은 화면뿐이다.
- 정밀·공 하나씩 공격 화면에 **7번 "히트 앤드 런"** (1루 주자가 있고 2루가 비었을 때만). 누르면 이번 공에 걸리고, 스윙 종류는 그대로 고른다.
- 도루(6번)와 같은 공에 둘 다 걸 수 없게 한다.

### 4.5 균형 (B1~B3)

- B1: `hitPlay`에서 타자가 **송구를 틈타** 더 간 베이스는 안타 종류에 넣지 않는다(`batTried`와 따로 `hitBases`를 기록). 기록·중계·함성은 `hitBases`를 쓴다.
- B2: 전진 수비 효과 재측정. 목표: 주자 3루 타율 상승 2푼 안팎.
- B3: 맞히기 삼진율 7% → 10% 안팎, 타율 차이를 강하게 < 보통 ≈ 맞히기(장타는 강하게가 뚜렷이 높게)로. `tests/sim.js`에 **상황별 표**(주자 5가지 × 스윙 3가지)를 넣어 단계마다 본다.
- 목표 수치(보통 난이도, 사람이 무난히 고를 때): 타율 .300~.330, 팀 득점 5점 안팎, 홈런 1.0. 현실 난이도는 타율 .260, 4.3점.

### 4.6 중계·소리

- **이닝 끝(C1)**: `inningLog`로 고른다. 삼자범퇴 → "깔끔하게", 주자 내보내고 무실점 → "위기를 넘깁니다", 실점 → "○점을 내주고 이닝을 마칩니다", 병살로 끝 → "병살로 불을 끕니다", 잔루 만루 → 아쉬움. (새 녹음 필요: 아래 목록)
- **함성(C2)**: `cheer`를 사건의 `contact` 뒤 **공이 떨어지는 시각**(`hitT`)에 맞춘다. 강도: 안타 < 장타 < 홈런 < 역전·끝내기. 원정팀 득점이면 탄식 섞인 작은 함성.
- **수비수(C4)**: 포지션 9개 × "~ 앞으로 / ~ 쪽으로 / ~가 잡았습니다" + "1루로·2루로·3루로·홈으로 송구합니다". 선수 이름은 계속 부르지 않는다(조각 방식의 한계).
- **미트 소리(C5)**: 파일이 없으므로 합성(짧은 저음 "퍽" + 가죽 잡음)으로 먼저 넣고, 녹음을 받으면 바꾼다. 스트라이크·볼·헛스윙 모두 공이 도착하는 순간(`tl.contact`).
- **안 쓰는 25줄(C3)**: 대부분 상황 판단이 필요해 빠져 있던 것 → 사건 목록이 생기면 붙인다(`c_twostrike`: 2스트라이크가 되는 순간, `c_late`·`c_last`: 7회·마지막 이닝 시작, `a_behind1`·`a_big1`·`a_flow1`: 점수 차, `r_tp`: 삼중살, `p_set1~3`: 투구 전 뜸).
- **해설 스타일(C6)**: `voice/index.json`에 `style` 칸을 두고(`calm` 지금 것, `hype` 새 것), 같은 아이디의 다른 스타일 녹음을 `voice/hype/…`에 둔다. 설정에서 고른다. 없는 줄은 기본 스타일로.
- **효과음 표**: 투구, 미트, 스윙, 타격, 파울, 땅볼 굴러가는 소리, 포구, 송구, 베이스 밟기, 심판 콜, 함성 → 사건 종류마다 하나씩 대응표(`SFX_MAP`)로 만들고 시각은 사건의 `t`.

### 4.7 접근성 (요구 4)

- **중계 통로를 고른다**: 설정 "경기 결과 전달" = 소리와 글 / 소리만 / 글만. 기본은 "소리와 글"(D1을 되돌리되, 화면 낭독기가 두 번 읽지 않게 결과 글에는 `aria-hidden`이 아니라 **낭독 대상에서만 빼고** 점자 단말기로는 한 줄씩 읽을 수 있게 `#log`에 남긴다).
- **진동 문법(D2)**: 스트라이크 짧게 1, 볼 길게 1, 안타 짧게 2, 장타 3, 홈런 길게-짧게-길게, 아웃 길게 2, 득점 짧게 3 + 길게. 설정에서 켜고, "진동 뜻 듣기" 항목으로 익힌다.
- 선택지마다 `aria-label`에 번호·이름·상태를 넣고, 상태가 바뀌면 `aria-live`로 **바뀐 것만** 알린다. 초점 순서: 질문 → 선택지 → 뒤로.
- 중계가 나오는 동안에도 고를 수 있음(이미 됨). 조작 안내 음성과 중계가 겹치면 중계를 줄인다(덕킹).
- 10개 넘는 선택지는 쪽을 나누지 않고 **두 자리 입력**(1, 0을 빠르게 → 10)을 허용(D4).
- 저시력 모드에서만 크게(이미 됨). 색만으로 구분하지 않게 볼카운트·주자에 글자·모양을 함께.

### 4.8 화면 보며 하기 (요구 5)

- 경기 화면 배치: 위 점수판 / 가운데 그림 / 아래 **상황 줄**(이번 공: 구종·구속·코스 점, 지난 공 3개 자취) / 선택지 / 능력치 패널.
- 능력치 패널: 타자(파워·컨택·선구안·주력·수비·송구), 투수(구속·제구·구위·체력·변화구·구종 숙련도). 파워와 체력은 큰 막대, 체력은 투구 수에 따라 줄어드는 것이 보이게, 컨디션 화살표(↑↓).
- 타구 방향·낙구 지점을 수비 장면에 선으로 남긴다. 스트라이크 존에는 투구 위치와 타자가 노린 칸을 함께 표시.
- `VIEW` 객체 하나에 "이 화면 방식에서 무엇을 어떻게 보일지"를 모아 A3를 정리한다. 경기 로직은 한 줄도 갈라지지 않는다.

### 4.9 설정 (요구 10, A4)

탭 6개, 화면 하나. 탭은 좌우 화살표·숫자 키로 옮기고, 탭 안에서는 1~9.

### 4.10 육성 (요구 6)

저장 호환: `L.career`·`life` 객체에 칸을 **더하기만** 한다. 불러올 때 `migrateCareer(c)`가 없는 칸을 채운다(`c.v` 버전 숫자).

- **성장**: 선수마다 `pot`(능력별 잠재 상한, 60~99), `curve`(조숙·보통·대기만성), `trait`(포지션 특화 2개). 훈련 효과 = 기본 × 나이 × (상한까지 남은 거리) × 컨디션. 상한에 가까울수록 느려져 "어디를 키울지"가 전략이 된다.
- **피로·부상**: `fatigue` 0~100. 훈련·경기로 쌓이고 휴식으로 줄어든다. 70을 넘으면 훈련 효과가 줄고 부상 확률이 오른다. 부상은 일수와 부위(능력 일시 저하)를 갖는다. 병원·휴식에 돈과 날짜가 든다.
- **경기 경험**: 출전·성적이 훈련과 별개로 성장 포인트를 준다(지금 `careerGrowFromGame` 확장).
- **계약**: `contract = { years, salary, bonus }`. 시즌 끝에 구단 제시액(능력·성적·나이·잠재력·인기) → 받기 / 올려 부르기(확률) / FA 선언(자격: 1군 일정 시즌). FA면 다른 구단 제시 2~3개 중 선택(팀 전력·홈구장·주전 여부가 다름).
- **경제**: 연봉은 월급으로 들어오고, 쓸 곳은 장비·강화·개인 코치·병원·휴가. 구단 예산은 내 연봉 상한과 FA 영입 경쟁에만 쓴다(구단 경영 게임까지는 가지 않는다 = 과한 복잡함 피하기).
- **장비**: 종류(배트·글러브·스파이크·보호대·포수 장비) × 등급 3 × 성격(예: 배트 = 컨택형/장타형/균형). 효과는 **작고 교환 관계가 있게**(장타형 +파워 −컨택), 내구도(경기마다 줄고 수리비), 강화(+1~+3, 실패 없음, 비용 증가). 총 보정 상한을 둬 "장비로 이기는" 일이 없게.
- 리그의 다른 선수에게도 나이·잠재력을 적용해 리그 전체가 세대교체된다(`league.js develop` 확장).

### 4.11 온라인 (A5)

- 방 상태에 `ver`(게임 규칙 버전 숫자)를 넣는다. 손님이 다르면 "두 기기의 버전이 다릅니다. 새로 고침해 주세요"를 띄우고 들어가지 않는다.
- `pendingThrow`, 히트앤런, 9단계 값은 방장이 계산하므로 손님은 선택만 보낸다. 선택 메시지에 새 종류 `throw`, `hitrun` 추가, 받을 때 차례·권한 검사.
- 상태 전체 전송은 유지(크기 측정만 시험에 넣는다: 200KB 넘으면 경고).

## 7. 위험과 호환

- **저장**: 설정·경기·리그·육성 모두 "칸 더하기 + 없으면 기본값". 진행 중이던 경기(`bb_game`)는 사건 목록이 없는 옛 형식일 수 있으므로 불러올 때 `G.v`를 보고 옛 형식이면 그 경기만 옛 방식으로 끝내거나 "새 버전이라 이어 할 수 없습니다"를 띄운다(조용히 깨지지 않게).
- **온라인**: 두 기기 버전이 다르면 막는다. 서비스 워커가 옛 파일을 잡고 있을 수 있으므로 버전 불일치 안내에 "새로 고침" 단추.
- **균형 변경은 육성·리그 기록에 영향**: Phase 2 뒤 리그 10시즌 자동 진행으로 기록 분포 확인.
- **송구 선택은 경기 속도를 늦춘다**: 기본은 "주자가 있을 때만 묻기", 시간 초과 6초, 끌 수 있음.
- 실제 기기에서만 확인되는 것(낭독기, 소리 경로, 카톡)은 자동 시험으로 대신할 수 없다. 단계마다 사용자 확인 목록을 낸다.
